# 异步视频任务计费闭环

## 结论

普通余额计费的异步视频任务采用“创建前冻结、成功后结算、明确失败后释放”的流程。订阅计费、同步直接返回完整视频、模型测试台以及图片、音频、文本请求保持原有计费逻辑。

## 状态与余额

### ZYCA 协议与模型隔离

协议以实际调度账号的 `video_request_profile=zyca` 为准，不通过模型名前缀判断。新增模型校验仅应用于该协议，其他账号的 `legacy`、`unified_json` 等协议继续使用原有逻辑。

| 上游模型 | 生成时长（秒） | 分辨率 | 参考图片／视频／音频上限 |
| --- | --- | --- | --- |
| `wan-3.0` | 5、10、15、30 | 480p、720p | 10／5／5 |
| `kling-4.0` | 3–30 | 720p、1080p | 10／5／3 |
| `seedance-2.5` | 4–30 | 480p、720p | 30／10／10 |
| `seedance-2.0` | 4–15 | 480p、720p | 9／3／3 |
| `seedance-2.0-mini` | 4–15 | 480p、720p | 9／3／3 |

Wan 提示词上限为 5000 个 Unicode 字符；Seedance 2.0 与 2.0 Mini 仅允许 16:9、9:16，像素尺寸也执行同一限制。其他已有模型限制保持不变。

客户端可使用 `zyca-wan-3.0`、`zyca-kling-4.0`、`zyca-seedance-2.5`、`zyca-seedance-2.0`、`zyca-seedance-2.0-mini`、`zyca-minimax-h3-903`。管理员必须在对应 ZYCA 账号显式配置别名到真实模型的映射，并配置匹配计费模型的售价及匹配上游模型的成本规则；系统不自动去前缀、不自动开放账号模型权限，也不为其他上游添加映射。

### ZYCA 固定按次价格

ZYCA 支持使用分组／渠道已有的按次计费配置：必须填写有效、非负的默认单价，且不能包含分档价格。每个任务计一次，不乘生成时长、不按分辨率选价。若将 Wan 不同分辨率统一按最高价格出售，应由管理员将该售价填入默认按次单价，并清除旧分档；价格不写死在程序中。

有效倍率和优惠仍沿用原有规则。希望默认单价即最终售价时，需配置有效倍率为 1，并核对优惠及用户分组倍率覆盖。旧分组视频价格覆盖渠道价格的优先级保持不变，迁移按次价格时也需检查该覆盖。账号统计成本必须独立配置，不能借用客户售价；免费价格／成本须显式填写 0。

异步任务预扣对 ZYCA 使用账号感知的价格估算入口，并检查账号标识一致性；其他协议继续使用原入口。费用快照、结算和失败释放流程不变。

### ZYCA 参考视频时长计费

`kling-4.0`、`seedance-2.5`、`seedance-2.0`、`seedance-2.0-mini` 在携带参考视频时，Sub 在提交上游和冻结余额之前向可信临时资源服务查询时长元数据，不下载视频，也不运行媒体探测器。临时服务在上传环节探测一次，并将结果绑定到按 SHA-256 命名的文件；相同内容已有有效元数据时复用。计费依据为生成秒数加每段参考视频分别向上取整后的秒数，不是合计后取整。例如生成 4 秒、参考 2.25 秒和 2.5 秒，计费时长为 4 + 3 + 3 = 10 秒。原始小数时长仍保存在 `reference_durations` 中，`reference_seconds` 为逐段取整后的累计秒数。参考列表与转发使用同一解析器，相同 URL 按既有规则去重。客户端提供的时长字段不参与费用计算，图片、音频不累计为视频秒数。

售价和成本分别按各自配置的计费模式处理：按秒配置乘累计时长，固定按次配置仍只计一次。Wan、无参考视频的请求与未列出的历史模型不需要元数据查询，其他上游协议保持原逻辑。ZYCA 按秒估算独立处理真实生成时长，不再受公共历史视频路径 15 秒上限截断。

余额预扣任务在既有 `UsageContextJSON` 中保存生成秒数、各参考视频秒数、累计秒数及内容 SHA-256，不保存参考视频原始 URL 或下载凭据。生成时长字段仍表示成片时长，不混入参考时长；结算使用创建时费用／成本快照，不重新下载、探测或按当前价格计算，也不重复加算参考时长。非余额预扣路径同样先计算完整费用／成本快照，再交给原用量记录路径。

安全与运行要求：

- 临时资源服务配置 `CANVAS_FFPROBE_PATH` 并提供对应可执行文件；Sub 不需要安装 `ffmpeg` 或 `ffprobe`。未开启探测或探测失败，不破坏临时服务原上传／下载功能，但该素材没有有效计费元数据，不能用于上述按时长计费的参考视频请求。
- Sub 通过 `gateway.zyca_trusted_media_origins` 配置精确的 HTTPS 来源列表（含端口，不支持域名后缀通配）。默认空列表，目标参考请求拒绝通过。必须填写真实临时资源服务返回 URL 的来源，不根据客户端请求、Host 或参数动态放行。
- 仅接受 `/temporary-media/<64位小写SHA-256>.mp4`、`.mov`、`.webm` 地址，不接受查询参数、片段、用户凭据或编码路径变体。Sub 根据该地址固定追加 `/metadata`，不采信客户端提供的元数据地址。
- 元数据接口返回 `version: 1`、`sha256`、`byteSize`、`mimeType`、`durationSeconds`、`expiresAt`。临时服务先确认原文件存在且未过期，再读取服务端生成的元数据；Sub 校验摘要与 URL 一致、类型匹配、大小为正、时长为有效正数且不超过 3600 秒、剩余有效期大于 5 分钟。
- 元数据 HTTP 请求最多 5 秒、响应最多 16 KiB，一组参考素材查询总预算 20 秒；禁止重定向，不携带客户端凭据，不使用环境代理，并复用公网连接防护。删除旧版 Sub 逐请求下载路径及其 200 MiB 限制，素材大小继续由临时上传服务和模型档案各自约束。
- 来源不可信、原文件已删除、元数据缺失、即将过期或查询失败时，在创建任务之前拒绝，不冻结余额，不把未知时长按 0 处理。旧素材缺少元数据时需要重新上传，不在查询时补探测。

本次范围只保证创建前的核验，不增加资源租约、保留期或容量淘汰保护，不覆盖校验通过后资源才被删除的情况。匿名上传限流和容量管理仍由临时资源服务负责，不属于 Sub 计费校验。逐段向上取整是管理员确认采用的保守计费策略，不代表已核实上游实际账单采用同一规则；成本快照同样按此策略估算，仍需 staging 对账确认。已有任务继续使用创建时保存的费用和成本快照，不追溯取整或补扣。

### Staging 验证要求

本次本地不执行测试或构建，以下项目应在隔离 staging 验证后再考虑生产发布：

1. 临时资源服务先配置 `CANVAS_FFPROBE_PATH` 并验证上传后能读取 `/metadata`，再为 Sub 配置可信 HTTPS 来源。运行临时资源服务用例，以及 Sub 的 `TestZYCA`、`TestVideoAccountStats`、`TestVideoReservation`、`TestVideoTaskBilling`、`TestOpenAIVideo` 用例。
2. 验证 MP4／MOV／WebM：生成 10 秒、参考 5 秒按 15 秒计算；生成 30 秒、参考 5.25 秒按 36 秒计算；生成 4 秒、参考 2.25 秒和 2.5 秒按 10 秒计算。覆盖整数、不足一秒和刚超过整数的参考时长，核对原始时长、售价、成本、倍率、冻结和最终用量快照。
3. 验证无参考视频的 30 秒 ZYCA 模型不截为 15 秒；Wan 的 480p／720p、5／30 秒任务均使用同一默认按次价。
4. 验证非白名单来源、重定向、摘要／类型不符、缺失／过期元数据、被删除原文件和查询超时：在提交上游前拒绝，不产生余额冻结。上传坏视频或临时服务缺少探测器时，旧上传行为保持不变，Sub 拒绝将其用于参考时长计费。
5. 验证成功结算、重复查询、失败释放、非预扣路径及旧任务快照兼容；验证相同模型名在 `legacy`、`unified_json` 协议下仍走原路径。
6. 验证同一内容重复上传复用探测结果，Sub 只请求小体积元数据、不下载视频；以真实上游账单确认小数秒计费精度。测试产生真实费用须单独确认。别名映射、默认按次售价、独立成本价及有效倍率仍需在 staging 配置，不自动修改线上配置。

### 既有模型与任务流程

ZYCA 视频适配接受 `agnes-video-2.5-flash` 和历史名称 `auto-video`，两者均限制为 720p、1 至 12 秒、最多 5 张参考图片，不接受视频或音频参考。发送给上游的模型名称由账号模型映射决定；如需兼容历史名称，应显式配置 `auto-video → agnes-video-2.5-flash`。名称兼容不修改售价、上游成本或历史任务快照；新名称的价格与账号统计成本必须分别配置，零成本应显式填写 `0`。

- 提交上游前按现有视频价格、分辨率、时长和有效倍率计算预计费用，并在同一数据库事务中扣减可用余额、增加冻结余额、创建账单记录。
- 上游返回任务 ID 后，账单保存平台、用户、API Key、分组和实际调度账号。Redis 仅作快速绑定，数据库记录是缓存过期后的事实来源。
- 创建任务时同时保存完整费用快照；后续结算使用创建时价格和归属，不因 API Key 被软删除或换组而重新定价、阻塞扣款。
- 上游明确成功且响应中存在可验证视频产物时，写入一次用量记录并结算冻结金额，不再次扣减可用余额。
- 上游统一视频文档的完成响应通过 `data[0].url` 返回成片地址，也可指向 `/v1/videos/{task_id}/content`；两种形式均视为可验证产物。
- 上游明确返回 `failed`、`cancelled`、`expired` 或 `error` 时，失败状态优先于响应中夹带的视频地址，始终释放冻结金额。
- 网络错误、超时、HTTP 429、HTTP 5xx、响应无法解析、轮询失败以及完成状态缺少视频产物时，任务保持 `unknown`，冻结金额不结算也不释放。
- 创建请求已经发出但没有拿到任务 ID 时，记录为 `submission_unknown / manual_review`。系统不会换账号重发创建请求，避免生成两个收费任务。

## 用户停止

用户点击停止、关闭页面或前端轮询超时，只停止浏览器等待，不调用上游取消接口，也不触发退款或释放冻结。当前上游视频文档没有任务取消接口。

## 后台补查

后台 reconciliation Worker 使用数据库租约抢占到期任务，并始终查询账单保存的原账号：

1. `pending / processing / unknown` 查询上游状态；
2. 成功且有产物时结算；明确失败时即使响应夹带视频地址也释放；
3. 查询异常只记录错误和下次查询时间；
4. `settling` 在进程重启后继续完成用量记录和冻结结算；
5. 超过提交确认期限仍没有任务 ID 的记录转人工确认，绝不重新创建。

所有结算和释放均有账单状态门，重复查询、多个实例并发补查或进程重启不会重复扣款、重复退款。

## 管理员人工核对

管理后台新增独立“异常视频任务”页面，复用现有管理员鉴权和操作审计，不改变管理员角色体系。列表只包含 `manual_review`、`settling` 和 `reserved + unknown`，支持按用户邮箱、用户名、用户 ID、API Key、请求 ID、上游任务 ID、原账号、平台、模型和状态筛选。

- 有上游任务 ID 时可“重新核对”，系统只使用账单保存的原上游账号查询；成功且有可验证产物才结算，明确失败时始终释放，其余结果继续待确认。
- 无上游任务 ID 时不能自动重新核对。管理员须在上游控制台、账单或工单中核实，再填写可追溯依据，人工确认成功或失败。
- 人工确认失败使用数据库锁在同一事务中校验异常状态并释放冻结；普通 `processing` 任务和 `settling` 任务不能人工释放。
- `settling` 表示已确认成功但用量写入或结算尚未完成，只能重试成功结算，不能转失败退款。
- 页面不提供重新生成或上游取消；用户主动停止本地等待也不会进入人工退款规则。

冻结、结算和释放成功后都会失效余额缓存，数据库余额仍是多实例并发下的事实源。

## 用户与上游账号删除

- 用户或上游账号仍关联 `reserved`、`manual_review`、`settling` 视频账单时，管理端拒绝删除，并提示先完成异常视频任务核对。
- 删除父账号时同时检查父账号及其 Spark 影子账号；任一账号存在未决视频账单时，一个账号都不会删除。
- 视频冻结与相同用户、相同上游账号的删除使用数据库事务级锁串行化。删除先完成时，后续冻结会因主体已删除而失败；冻结先完成时，删除会看到未决账单并拒绝执行。
- 已完成 `captured` 或 `released` 的历史账单不阻止删除；API Key 仍可按原有流程软删除，后续结算使用任务创建时保存的归属和费用快照。

## 数据表

迁移 `222_video_task_billings.sql` 创建 `video_task_billings`。表中只保存业务 ID、任务状态、计费金额、查询租约和必要的用量上下文，不保存 API Key 明文、Cookie 或上游凭据。

## 验收重点

- 余额不足时不得请求上游；并发请求的冻结总额不得超过可用余额。
- 明确创建失败或终态失败应只释放一次。
- 创建超时、查询 429/5xx 和完成无产物应保持冻结与待确认。
- 成功任务应只产生一条用量记录，余额不得二次扣减。
- 用户停止前端等待不应调用取消或退款接口。
- Redis 任务绑定失效、浏览器关闭和服务重启后，后台仍能按原账号完成闭环。
- API Key 删除或换组后，成功任务仍应按创建时价格完成结算。
- 未决视频账单应阻止用户、原上游账号及其父子影子账号删除；并发删除和视频冻结不得产生悬挂账单。
- 人工核对必须记录依据；重新核对不得换账号，普通执行中任务不得被管理接口释放。
