# 上游功能与定制功能兼容说明

当前兼容官方 `v0.2.19` 主线（`d851a38477597157e78450d30af2d8504764d085`）。Go 工具链及各构建入口统一为 `1.27.3`，前端使用 Vue I18n 11；定制语言包仍在基础语言包之后覆盖。

## 分组与模型准入

`model_allowlist` 同时约束模型列表和网关请求准入。开启后，客户端提交的公开模型名必须命中白名单；合成分组先校验公开模型名，再解析目标平台和改写上游模型。Live 使用 `session.model`，普通请求使用对应协议的模型字段。模型改写同步更新请求缓存和重试 reader。

网关读取请求体前必须经过定制内存准入，白名单、合成路由和处理器共享同一份缓存。`/images/generations` 与 `/v1/images/generations` 都保留异步请求分派。

模型候选接口为 `GET /api/v1/admin/groups/:id/model-allowlist-candidates`，图像增强的目标模型选择也使用该接口。分组授权用户、默认 API Key 分组、自动承接、号池可见性、缓存命中转移、活动折扣及图像增强参数仍通过定制管理接口保存和校验。

普通模式删除分组保留目标分组迁移规则；简易模式仅允许删除空分组，不得先迁移 API Key 再尝试空组删除。用户删除继续受未结算视频任务保护。

## 计费与错误处理

账号成本与用户售价使用同一请求的定价时刻，保留高峰、低峰、推理等级、视频成本和 Fast SKU 策略。认证快照同时保存上游白名单和定制授权、计费字段；版本变化后旧缓存重新加载。

`GET /v1/sub2api/billing` 通过请求头 `X-Sub2API-Billing-Promo: 1` 协商活动折扣能力。携带该值时，`group_rate_multiplier`、`user_rate_multiplier`（如有）与 `resolved_rate_multiplier` 返回折前基准，`effective_rate_multiplier = resolved × applied_peak × applied_promo`。未携带或值不为 `1` 时，三项基准均折入查询时刻的活动折扣，保持 `resolved = user ?? group` 和 `effective = resolved × applied_peak`，兼容不认识活动字段的官方下游探针。活动信息字段仍保留；关闭活动或处于窗口外时活动因子为 `1`。

本定制版探针在应用账号自定义请求头之后设置上述能力声明，按窗口现算高峰与活动因子，并仅将折前 `resolved` 同步到账号静态倍率列，避免冻结短期折扣或重复计算。旧客户端看到的活动倍率随重新探测更新，无法仅凭旧协议在活动边界自动恢复折前基准。

Chat Completions 共享发送层统一处理传输错误，调用方直接返回该错误，避免重复记录或重复执行账号处理。客户端错误消息保留 `reasoning.mode` 和 `reasoning.effort` 参数路径，上游 URL、其他域名和 IP 继续脱敏。

GPT-6.1 Terra 接入模型别名、能力目录和定制 Fast SKU 策略。已配置的分组、渠道及 Fast 档报价保持优先，默认目录仅补齐缺失档位；DeepSeek Pro 不再按已过期的日期规则降为 Flash 价，峰谷计费仍按请求时刻计算。

Anthropic 兼容流断开后继续读取上游用量用于结算；只有已交付有效内容且收到成功终态时才执行缓存命中扣减调整。失败、取消或不完整终态不能推进累计调整状态。

## 图片端点与用户功能

OpenAI OAuth 和 Setup Token 账号在完成渠道及账号模型映射后，为 Image 1.5、Image 2 和已列出的 Image 2.5 模型选择 Codex Images 原生端点；仅端点返回 404/405 时回退到 Responses。原生响应同样经过定制图片增强和本地文件存储，`response_format=url` 的完成结果返回 `/generated-images/` 地址；原始上游用量在增强前读取，图片缓存 token 按明细计费。Gemini 流式图片继续去重，同时保留上游异常响应识别。

`image_count_billing` 对 OpenAI、Composite 分组的专用图片端点生效，可以在渠道采用 token 定价时强制按张结算。关闭开关不取消既有定制图片单价规则；已有分组模型价优先于分组图片兜底价，分组图片价优先于渠道图片价。图片数量始终来自实际响应，不以请求 `n` 或开关估算，零张不收费。Gemini 的 `inlineData`、`fileData`、snake_case 及增量/累积流统一按最终图片内容或引用去重，排除 thought 中间图片。

图片下载上限保留 64 MiB，上传的单个图片 part 上限为 50 MiB；超限上传直接拒绝，不截断后继续转发。

订阅公开开关采用默认启用语义，只有显式关闭才隐藏订阅入口并拦截用户订阅页。抽奖、签到、自定义菜单顺序和模型测试台仍使用各自开关。用户仪表盘合并平台用量与已配置配额，按用量金额排序；余额和费用保留灵石单位，管理端费用详情显示八位小数。支付渠道继续遵守定制的统一可见按钮与唯一来源规则。侧栏购买入口使用定制页面 `/payment`，文案随站点计费模式切换；`/purchase` 保留跳转兑换码页 `/redeem` 的历史行为。

## 管理权限与账号状态

受限管理员 API 密钥按操作和资源范围授权，账号查询复用定制列表筛选并在 SQL 中施加范围限制。MCP 使用独立 OAuth 授权，由部署配置 `MCP_PUBLIC_URL` 启用；未启用时侧栏隐藏入口。用户停用、角色降级会在同一数据库事务中撤销对应 MCP 授权，原有分组黑名单同步仍保留。

账号普通编辑在行锁中保留最新门票、Grok 模型目录和上游模型能力元数据，拒绝旧表单覆盖这些受管状态。调度缓存接入上游的版本化进程内快照，保留定制轮候、根账号独立容量及代理故障冷却；认证快照版本为 30，旧快照自动重建并携带全部定制计费字段。

## 数据迁移与验证

迁移 235 将 `groups.models_list_config` 改名为 `model_allowlist`，保留原配置；迁移 236 修复旧列、双列或缺列状态；迁移 237 扩展 MiniMax 平台约束。已有列表过滤配置开启时，升级后也会限制请求准入，需要核对公开模型与合成别名。

两份 238 迁移分别扩展 OpenCode 平台约束和删除三档限额全为空的配额记录。迁移按完整文件名排序及记录，同编号不会互相覆盖；没有配额记录表示不限额，已有任一限额的记录保持不变。回滚前必须核对新增平台数据及配额清理的兼容性，需要恢复清理前记录时使用对应数据库备份。

迁移 `246_enable_gemini_image_generation_groups.sql` 将已有 Gemini、Antigravity 分组的生图开关置为开启，以兼容新准入规则；升级验收需核对需要禁用生图的分组。新增 `247_scoped_admin_api_keys.sql`、`248_group_image_count_billing.sql`、`249_mcp_oauth.sql` 分别建立管理密钥、分组开关和 MCP 授权存储，与同编号的 Excel、账号测试迁移按完整文件名独立执行，不更名或改写已应用迁移。

staging 使用独立 PostgreSQL、Redis、运行配置、数据目录和公开 `18080` 端口。执行涉及列重命名的升级前保存 staging 数据库备份及原镜像。回退到仍查询旧列的镜像时，必须同时恢复兼容数据库结构，不能仅切换镜像。

发布验证包括后端单元测试、前端完整测试与构建、生成代码、发布门禁、数据库迁移、容器和 HTTP 健康检查。语言包完整性检查按运行时顺序合并基础语言包与定制覆盖。
