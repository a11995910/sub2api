# 上游功能与定制功能兼容说明

## 分组与模型准入

`model_allowlist` 同时约束模型列表和网关请求准入。开启后，客户端提交的公开模型名必须命中白名单；合成分组先校验公开模型名，再解析目标平台和改写上游模型。Live 使用 `session.model`，普通请求使用对应协议的模型字段。模型改写同步更新请求缓存和重试 reader。

网关读取请求体前必须经过定制内存准入，白名单、合成路由和处理器共享同一份缓存。`/images/generations` 与 `/v1/images/generations` 都保留异步请求分派。

模型候选接口为 `GET /api/v1/admin/groups/:id/model-allowlist-candidates`，图像增强的目标模型选择也使用该接口。分组授权用户、默认 API Key 分组、自动承接、号池可见性、缓存命中转移、活动折扣及图像增强参数仍通过定制管理接口保存和校验。

普通模式删除分组保留目标分组迁移规则；简易模式仅允许删除空分组，不得先迁移 API Key 再尝试空组删除。用户删除继续受未结算视频任务保护。

## 计费与错误处理

账号成本与用户售价使用同一请求的定价时刻，保留高峰、低峰、推理等级、视频成本和 Fast SKU 策略。认证快照同时保存上游白名单和定制授权、计费字段；版本变化后旧缓存重新加载。

Chat Completions 共享发送层统一处理传输错误，调用方直接返回该错误，避免重复记录或重复执行账号处理。客户端错误消息保留 `reasoning.mode` 和 `reasoning.effort` 参数路径，上游 URL、其他域名和 IP 继续脱敏。

## 数据迁移与验证

迁移 235 将 `groups.models_list_config` 改名为 `model_allowlist`，保留原配置；迁移 236 修复旧列、双列或缺列状态；迁移 237 扩展 MiniMax 平台约束。已有列表过滤配置开启时，升级后也会限制请求准入，需要核对公开模型与合成别名。

staging 使用独立 PostgreSQL、Redis、运行配置、数据目录和公开 `18080` 端口。执行涉及列重命名的升级前保存 staging 数据库备份及原镜像。回退到仍查询旧列的镜像时，必须同时恢复兼容数据库结构，不能仅切换镜像。

发布验证包括后端单元测试、前端完整测试与构建、生成代码、发布门禁、数据库迁移、容器和 HTTP 健康检查。语言包完整性检查按运行时顺序合并基础语言包与定制覆盖。
