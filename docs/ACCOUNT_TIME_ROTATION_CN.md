# 智能运维：时段轮候

管理员通过「智能运维 → 时段轮候」配置 OpenAI OAuth 账号的每日轮换。支持手动模式和智能模式；只有独立 OAuth 根账号可加入，API Key、其他平台和 Spark 影子账号不参与。所有时段固定按北京时间（UTC+8）每日重复，不依赖浏览器或服务器时区。

新配置默认停用。历史配置没有 `mode` 时按手动模式读取，保持原有行为。保存时需要选择模式、账号池并启用；智能模式保存成功后即可使用，不需要基线采集、观察期或上线后学习。

## 智能模式

智能模式以当前时段的主力名额、固定轮换周期和有效额度信息决定新请求的账号偏好，不改写 `accounts.priority`，也不启停账号。默认安排为：

| 北京时间 | 主力账号数 |
| --- | ---: |
| 00:00–08:00 | 1 |
| 08:00–10:00 | 2 |
| 10:00–14:00 | 4 |
| 14:00–18:00 | 4 |
| 18:00–22:00 | 3 |
| 22:00–24:00 | 2 |

白天保留更多主力，夜间仍有账号承接请求。时段和主力数可编辑：支持 1 至 24 个时段，必须无重叠、无空档地覆盖 `00:00–24:00`，单段不跨午夜；每段主力数为 1 至 10000。实际可用账号不足时，主力数自动取可用数量，不创建或自动扩容账号。

默认每 60 分钟轮换一次，可设置为 15 至 240 分钟且必须整除 1440。轮换按照北京时间的固定周期推进；时段边界也会立即调整主力名额。符合条件且未触及额度保留线的账号组成稳定轮换环，每轮向前移动一位，同一时刻和同一候选范围会得到相同结果。不同套餐的剩余额度百分比不用于推断绝对容量，也不用于将某个套餐长期固定为主力。

账号在计划中展示为四种角色：

- **主力**：当前轮次优先承接新会话的账号；同层仍使用现有优先级、负载等调度规则。
- **备用**：等待后续轮换，主力无法承接时可接班。未加入智能账号池但满足请求条件的账号仍保留在普通备用层。
- **额度保护**：有效的 7 天或 5 小时剩余额度触及保留线后降低新请求优先级，其他候选无法承接时仍可兜底。默认保留线为 10%，可设置 1% 至 50%。这不是硬性停用或额度保证，已有粘性会话和兜底请求仍可能继续消耗额度。
- **不可用**：账号不符合类型、状态、到期、限流或冷却等可调度条件，或不在当前候选范围内；智能轮候不会绕过这些限制。

额度仅采用有效窗口：窗口分钟数必须大于零、使用比例有效、重置时间尚未到达，额度采样时间不得晚于当前时间且距今不超过 8 小时。零窗口、缺少采样时间、过期采样或已经到达重置时间都显示为未知，不能把 `0%` 与零窗口组合当作满额。未知额度不等于耗尽，账号仍可轮换；界面会给出未知提示。该机制不假设休息 5 小时就能恢复额度。

粘性会话保持原有规则，不因轮次切换主动迁移，也不抢占或中断已有请求。原有规则仍可能因更高优先级账号有容量、账号限流或不可用等条件重新选择。分组、模型能力、限流和账号状态过滤仍然有效。智能偏好应用于旧版及高级 OpenAI 调度路径，只对当前请求合法的候选排序。新会话依次尝试主力、备用和保护账号，各层保留原有调度规则；主力满载时可转向备用，健康候选不会因为超出主力名额或排序截断而失去兜底机会。主力数不是流量配额，不保证某一账号取得固定流量比例，也不强制全部请求在时段边界迁移。

## 手动模式

手动模式保留固定 3 个可编辑时段，默认分别为 `00:00–08:00`、`08:00–16:00`、`16:00–24:00`。每段可选择多个账号，也可留空；每个账号只能归属一个时段。不同账号组的时段允许重叠或留有空档。

时间精度为分钟，包含开始、不包含结束。结束时间支持 `24:00`；结束早于开始表示跨午夜。开始和结束相同会被拒绝，全天可写为 `00:00–24:00`。每段独立设置时段内和时段外优先级，均为 `1–2147483647` 的整数，数值越小越优先，默认分别为 `1` 和 `50`。

保存启用配置后立即应用当前时刻的优先级。后台启动时立即校正，此后每 15 秒检查一次；调度缓存通过现有 outbox 消费机制更新，实际生效还需等待缓存消费。服务故障期间不执行轮候，恢复后按当前时间补偿，不回放历史时段。

手动模式只改变 `accounts.priority`，不强制账号停用，不抢占或中断已有请求。粘性会话、分组优先级、限流、订阅类型及其他调度规则仍然有效，因此优先级变化不保证全部流量立即换组。

## 账号编辑、切换和恢复

账号编辑页显示轮候模式和设置入口。手动轮候启用时不能手工修改受管账号的优先级，编辑其他字段时也不提交弹窗打开时的旧优先级；停用后仍显示已配置提示，并允许手工修改。智能模式不接管账号原优先级，因此不锁定该编辑项。配置读取失败时暂时保留优先级，重新打开可重试。

手动模式首次接管账号时保存原优先级，修改时段或在时段间移动账号不会覆盖该原值。停用、移除账号或切换到智能模式时，在同一事务中恢复原优先级并清理恢复记录。再次启用手动模式时，以账号当时的优先级建立新的恢复基线。通过其他接口或批量编辑修改手动受管账号的优先级，会在下一次轮候检查时被配置值覆盖。

账号被删除时清理其手动恢复记录，不阻塞其他账号；账号不再满足 OpenAI OAuth 条件时恢复原优先级并停止管理。配置页保留失效账号的 ID 提示，管理员可移除。启用保存时拒绝不存在或不符合类型条件的账号；停用保存不受失效账号阻挡。可选类型校验不等同于实时可用性校验，已停调或处于冷却期的账号在智能计划中显示不可用。

## 运行快照与故障降级

后台每 15 秒成功应用配置后发布独立内存快照；保存成功也立即发布。调度热路径只读取快照和当前请求已有的账号候选，不为智能轮候额外查询数据库。智能模式的周期检查不锁定整个账号池，不反复写账号优先级，也不生成优先级变更通知；从手动模式切入时必要的原值恢复除外。

快照超过 45 秒没有成功应用更新时，智能偏好停止生效，调度器继续使用原有优先级、负载、粘性和兜底机制。后台恢复后再次应用当前配置即可恢复智能偏好。读取配置或状态接口不会延长快照有效期；低于当前版本的执行结果也不能覆盖或续期新快照。

状态页展示已保存配置的运行计划、角色及原因。全局计划用于查看账号池概况；带分组查询时仅预览该组的候选。实际请求还会按模型、限流和负载等条件筛选，计划预览不等同于每次请求的最终选择。

管理页面在智能模式下每 20 秒自动刷新已保存配置的运行状态；手动刷新前如果存在未保存编辑会保留当前编辑并提示先保存或放弃。账号池列表同时显示账号的调度状态、限流/过载/临时冷却及到期信息，便于在加入轮候前识别当前不可用账号。状态接口仍以已保存配置为准，不会把尚未保存的编辑当作运行计划。

## API 与持久化

管理员接口沿用管理员认证、面板限流、合规和审计中间件：

- `GET /api/v1/admin/intelligent-ops/time-rotation`：读取配置，无配置时返回停用的手动模式及两种模式的默认参数。
- `PUT /api/v1/admin/intelligent-ops/time-rotation`：整体保存配置并立即应用。必须携带读取时的 `revision`；配置已被其他管理员更新时返回 409，需重新加载。
- `GET /api/v1/admin/intelligent-ops/time-rotation/status`：读取执行快照状态与当前智能计划，可选 `group_id` 限定分组。返回 `mode`、`enabled`、`revision`、`ready`、`updated_at`、`period`、`next_rotation_at`、`accounts` 和 `scope`。`updated_at` 为执行器最近成功应用时间，不是额度采样时间；`ready` 表示快照新鲜且与已保存版本一致，不表示所有账号可用。停用、手动模式或快照未就绪时不返回智能账号计划。

配置公共字段为 `enabled`、`revision`、`mode`、`slots` 和 `smart`：

- `mode` 为 `manual` 或 `smart`，省略或空值兼容为 `manual`。
- `slots` 为手动模式的三个时段，每段包含 `start`、`end`、`account_ids`、`active_priority`、`inactive_priority`。智能模式单独提交时可省略 `slots`，后端补齐空账号的默认三个手动时段。
- `smart` 包含 `account_ids`、`periods`、`rotation_minutes`、`quota_reserve_percent`；每个智能时段包含 `start`、`end`、`primary_count`。启用智能模式时至少选择一个账号，账号 ID 必须为正整数且不重复。
- 状态接口的 `accounts` 项包含 `account_id`、`name`、`role`、`reason`，以及有有效额度时的 `quota_7d_remaining` 和 `quota_5h_remaining`。角色值为 `primary`、`standby`、`protected` 或 `unavailable`；未知额度字段不返回数值。

配置与手动模式的原优先级保存在现有 `settings` 表的 `account_time_rotation` 记录中，无需新增数据库迁移。原优先级仅由后端维护，不接受客户端提交，也不通过配置接口返回。配置保存、原值恢复、账号优先级和调度 outbox 通知使用同一事务；任何一步失败全部回滚。配置行锁串行化多实例执行及管理端保存，只在实际变化时写入账号和通知，失败后下一轮重试。

回滚到不支持智能模式的版本前，必须先停用轮候并确认手动原优先级已恢复。旧版本可能忽略 `mode` 和 `smart` 而按保留的 `slots` 执行手动轮候；仅切换到智能模式不能作为回滚前停用。更早的不支持轮候的版本也不会自动恢复留存配置。
