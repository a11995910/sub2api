# 智能运维：账号轮候

管理员通过「智能运维 → 账号轮候」管理 OpenAI OAuth 独立主账号。支持按请求表现自动降权的智能模式，以及固定时段的手动模式。API Key、其他平台和 Spark 影子账号不参与。配置默认停用；缺少 `mode` 的历史配置按手动模式读取。

## 智能模式

智能模式依据选中账号最近完成的真实请求判断健康，不再使用昼夜时段、主力名额、固定轮换周期或额度保留线。现有额度、限流、模型、分组、到期、停止调度等约束仍独立生效。

| 配置 | 默认值 | 允许范围 |
| --- | ---: | --- |
| 首字慢请求阈值 | 20 秒 | 1–300 秒 |
| 连续慢请求数 | 3 次 | 2–20 次 |
| 连续健康请求数 | 3 次 | 2–20 次 |
| 连续样本窗口 | 10 分钟 | 1–120 分钟 |
| 降权等待时间 | 30 分钟 | 1–1440 分钟 |
| 等待优先级 | 50 | 1–2147483647 |
| 观察请求最小间隔 | 60 秒 | 1–600 秒 |

连续样本窗口必须大于 `(健康与慢请求次数中较大值 - 1) × 观察间隔`。实际请求本身也需要时间，应给采样窗口留出余量。健康是请求成功、未报告客户端断开、存在有效首字数据且首字小于配置阈值；恰好达到阈值算慢。此处健康标准独立于其他页面的颜色分级。

请求按完成顺序统计。慢、健康两种样本相互打断连续计数；失败、取消、缺失首字数据也会打断连续计数，不会当作健康。连续样本必须落在从本轮第一个样本开始的窗口内，超时后从当前样本重新统计，不能把昨天的请求累计到今天。成功的非流式请求若没有首字数据，仅展示返回耗时，不用总耗时代替首字。

智能轮候账号在 Responses SSE、Chat/Messages 桥接和标准 WebSocket 转发中按实际内容输出计首字，排除初始化元数据、空事件和保活；WebSocket 直通沿用输出 delta 的计时口径。未加入智能轮候的账号保留现有 TTFT 设置。整次返回耗时同时展示，但不单凭总耗时判断能力下降，避免长回复误伤。失败与限流继续交给既有健康保护处理，不把任意业务错误归因为首字变慢。

| 状态 | 行为和转换 |
| --- | --- |
| 正常 `normal` | 使用账号设置的优先级。窗口内连续 3 次首字达到 20 秒，进入等待。 |
| 轮候等待 `cooling` | 作为备用，在其他合格候选无法承接时接流量；运行时优先级取原值和等待优先级的较大者。等待期绿色请求不会提前恢复。 |
| 观察恢复 `recovering` | 等待结束后进入观察。合格真实请求给予试用机会；每账号最多一个在途观察请求，默认至少间隔 60 秒。连续健康达标才恢复正常；连续慢再次达标则重新等待。 |
| 不可用 `unavailable` | 账号已删除、不满足类型或现有调度条件。健康状态不能绕过这些限制。 |

等待期不是硬停用；所有账号都变慢时，仍保留备用能力。首字慢表示当前请求表现不佳，并不能单独证明账号本身故障，也可能来自模型、长输入或上游拥堵。当前按账号统计，不做跨模型归因。

观察使用真实业务流量，不额外发送付费探测请求。没有合适流量时保持观察，不凭时间恢复；请求失败、缺少首字或长时间间隔均可能延长观察。等待前已开始的长请求不会被用来证明等待后的恢复。普通可迁移粘性会话不再绕过降权；到期观察机会不会被普通粘性长期饿死。必须保持原账号的上下文和任务归属仍保留原有约束，不中断在途请求或强制迁移不可迁移上下文。观察账号不进入普通并发等待队列，防止绕过试用限额；不可迁移上下文的固定账号请求是例外，仍按原并发规则承接，不因试用限额误换账号。

## 优先级与配置变更

优先级数字越小越优先。智能模式始终不覆盖 `accounts.priority`，而在调度时施加临时偏好。默认等待优先级为 50，原值为 70 时仍保留 70，避免反向提权。等待账号处于备用层，观察机会、正常账号先尝试；同层按现有调度规则选择。未选账号与正常账号处于同层。

管理员可以在等待期间修改账号原优先级，恢复时使用最新设置。停用智能轮候、切回手动模式或移除账号会清理对应健康状态和临时限制。修改健康规则会重置连续计数，保留已经开始的等待截止时间，后续新等待使用新配置。

历史智能日程配置没有健康字段时，自动补齐默认健康规则；旧 `periods`、`rotation_minutes`、`quota_reserve_percent` 不再参与调度。历史手动配置不变。从手动切入智能时，事务内恢复手动模式保存的原优先级。

## 手动模式

固定三个可编辑时段，默认 `00:00–08:00`、`08:00–16:00`、`16:00–24:00`，每日按北京时间重复。每个账号只能加入一个时段，各段可以留空、重叠或留有空档。开始时间包含、结束时间不包含，结束支持 `24:00` 或跨午夜，不能与开始相同。

时段内、外优先级默认 1、50。首次接管保存原值，停用、移除、切换智能模式时恢复。手动受管账号的优先级编辑被锁定；其他入口对其优先级的改动会在下一次周期执行时被覆盖。删除账号会清理原值恢复记录，不影响其他账号。

## 运行状态、持久化和边界

执行器启动立即应用配置，此后每 15 秒运行。请求结果在本进程内即时更新健康状态；请求热路径不增加数据库访问。后台将健康快照保存到现有 `settings.account_smart_rotation_health`，正常退出时再保存一次，重启后恢复同一配置版本的等待和观察状态。异常退出可能丢失最后一次成功快照之后的样本。快照保存校验配置版本，避免旧执行器覆盖新配置；不修改账号表，也不新增数据库迁移。

健康计数和观察并发限制按应用进程执行，适用于当前单个正式应用实例；多实例接流前需要改为共享状态协调。staging 与 prod 的独立数据库天然隔离这些状态。

配置执行快照超过 45 秒未更新时，智能偏好失效，回退原有调度，页面标记状态过期；健康快照恢复失败时不会发布新配置快照，后台继续重试。配置和状态读取不会延长执行器快照有效期。

页面每 15 秒刷新已保存配置的状态，不混入未保存编辑。展示状态、原优先级和当前优先级、最近首字和返回耗时、样本时间、连续计数、等待结束或下次观察时间。时间按北京时间显示。全局状态不代表特定请求一定可以使用该账号；请求仍执行完整资格筛选。

## 管理接口

接口沿用现有管理员认证、面板限流、合规和审计：

- `GET /api/v1/admin/intelligent-ops/time-rotation`：读取配置。
- `PUT /api/v1/admin/intelligent-ops/time-rotation`：整体保存，需要读取时的 `revision`；版本冲突返回 409。智能模式启用时须选择至少一个有效的 OAuth 独立主账号。
- `GET /api/v1/admin/intelligent-ops/time-rotation/status`：读取已确认运行状态，可选 `group_id` 限定分组。未就绪、停用或手动模式不返回智能状态列表。

公共配置字段为 `enabled`、`revision`、`mode`、`slots`、`smart`。`smart` 使用 `account_ids`、`ttft_threshold_seconds`、`slow_request_count`、`healthy_request_count`、`sample_window_minutes`、`cooldown_minutes`、`waiting_priority`、`probe_interval_seconds`。部分填写的健康策略若包含非法零值会拒绝保存；健康字段全部缺省或全部为零时整体补齐默认值，以兼容历史配置。

状态列表每项包含 `account_id`、`name`、`role`、`reason`、`original_priority`、`effective_priority`、`slow_streak`、`healthy_streak`，以及有数据时的 `last_ttft_ms`、`last_duration_ms`、`last_sample_at`、`cooldown_until`、`next_probe_at`。顶层保留 `period` 和 `next_rotation_at` 兼容字段，健康轮候下均为 null；`updated_at` 是配置执行器时间，`last_sample_at` 才是账号最近请求结果时间。

配置及手动原值保存在 `settings.account_time_rotation`；原值只由后端维护。配置保存、手动原值恢复、优先级修改及 outbox 通知保持同一事务。回滚到旧版前先停用轮候并确认手动原值已恢复；旧版本不理解健康规则，不能直接沿用已启用的智能配置。
