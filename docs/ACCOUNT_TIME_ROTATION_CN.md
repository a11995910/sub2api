# 智能运维：时段轮候

管理员通过独立菜单「智能运维 → 时段轮候」配置 OpenAI OAuth 账号的每日优先级轮换。只有独立 OAuth 账号可选，API Key、其他平台和 Spark 影子账号不参与。

## 时间和优先级规则

- 固定 3 个可编辑时段，默认分别为 `00:00–08:00`、`08:00–16:00`、`16:00–24:00`，统一按北京时间（UTC+8）每天重复，不依赖浏览器或服务器时区。
- 每段可选择多个账号，也可留空；每个账号只能归属一个时段。不同账号组的时段允许重叠或留有空档。
- 时间精度为分钟，包含开始时间、不包含结束时间。结束时间支持 `24:00`；结束早于开始表示跨午夜。开始和结束相同会被拒绝；全天可写为 `00:00–24:00`。
- 每段独立设置时段内和时段外优先级，均为 `1–2147483647` 的整数，数值越小越优先。默认分别为 `1` 和 `50`。
- 保存启用配置后立即应用当前时刻的优先级。后台启动时立即校正，此后每 15 秒检查一次；调度缓存通过现有 outbox 消费机制更新，实际生效还需等待缓存消费。服务故障期间不执行轮候，恢复后按当前时间补偿，不回放历史时段。
- 轮候只改变 `accounts.priority`。它不强制账号停用，也不抢占或中断现有请求；粘性会话、分组优先级、限流、订阅类型及其他调度评分规则仍然有效，因此优先级变化不保证全部流量立即换组。

## 账号编辑和恢复

已选择的账号在「账号管理 → 编辑 → 优先级」处显示「已经设置时段轮候」、所属时段、两种优先级和设置入口。轮候启用时此处不能手工修改优先级，编辑其他字段时也不提交弹窗打开时的旧优先级。轮候停用后仍显示已配置提示，并允许手工修改；状态读取失败时暂时保留优先级，重新打开可重试。

首次启用时保存每个账号加入前的优先级。修改时段或在时段间移动账号不会覆盖该原值。停用整个轮候或从所有时段移除账号时恢复原值；再次启用会以当时的账号优先级建立新的恢复基线。通过其他接口或批量编辑修改受管账号的优先级，会在下一次轮候检查时被配置值覆盖。

账号被删除时清理其恢复记录，不阻塞其他账号；账号不再满足 OpenAI OAuth 条件时恢复其原优先级并停止管理。配置页保留失效账号的 ID 提示，管理员可移除。启用保存时拒绝不存在或不符合条件的账号；停用保存不受失效账号阻挡。

## API 与持久化

管理员接口（沿用管理员认证、面板限流、合规和审计中间件）：

- `GET /api/v1/admin/intelligent-ops/time-rotation`：读取配置，无配置时返回停用的默认三个时段。
- `PUT /api/v1/admin/intelligent-ops/time-rotation`：整体保存配置并立即应用。字段为 `enabled`、`revision` 和 `slots`；每段包含 `start`、`end`、`account_ids`、`active_priority`、`inactive_priority`。必须携带读取时的 `revision`；配置已被其他管理员更新时返回 409，需重新加载。

配置与原优先级保存在现有 `settings` 表的 `account_time_rotation` 记录中，无需新增数据库迁移。原优先级仅由后端维护，不接受客户端提交、不通过配置接口返回。配置保存、原值恢复、账号优先级和调度 outbox 通知使用同一数据库事务；任何一步失败全部回滚。配置行锁串行化多实例执行及管理端保存，只在实际变化时写入账号和通知，失败后下一轮重试。

回滚到不支持此功能的旧版本前，先停用时段轮候并确认原优先级已恢复；旧版本不会执行轮候或自动恢复留存配置。
