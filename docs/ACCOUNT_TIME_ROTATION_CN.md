# 账号轮候、严格休息与总限速

管理入口为「智能运维 → 账号轮候」。仅管理选中的独立 OpenAI OAuth 根账号。严格休息和总限速同步约束这些根账号的影子账号；未配置保护的账号保持原调度规则。所有排班固定使用北京时间，顶部「启用轮候」是手动轮候、智能轮候和两项保护的总开关。旧配置的 `strict_rest` 默认为 false，`request_limits` 默认为空。

## 配置方法

1. 选择手动或智能轮候，开启顶部总开关。
2. 开启「排班外严格休息」，在三个时段中选中根账号并设置可接请求的时间。每账号只能属于一段，允许跨午夜、重叠班次和空档。未排班的账号不受休息限制。
3. 点击「添加账号限速」，为每个需要限制的根账号设置滚动 60 秒总次数，例如先以 10 次作容量试运行参数，观察排队、拒绝率和业务响应后调整。这不是上游安全阈值。
4. 保存，查看下方「已保存配置的保护状态」。分组、模型、额度和账号状态仍决定账号是否真正可用。

需要全天服务时，应保证每个业务分组在各时段都有可用账号。不能只按全站账号数量平均分班。某分组的全部账号休息或触及上限后，系统可能返回无可用账号；不会放开保护来兜底。限速不自动排队等待一分钟，现有并发排队仍独立生效。

## 严格休息

`strict_rest=true` 时，`slots` 同时作为硬性准入时间表，手动和智能模式均适用。区间包含开始、不包含结束，结束支持 `24:00`，结束早于开始表示跨午夜。禁止为选中账号配置 `00:00–24:00`；起止相同也不合法。

调度候选、等并发槽复核及发送上游前检查时间。粘性会话、续链、兜底和重试不能绕过发送检查。HTTP 每次发送尝试、WebSocket 每个 `response.create`（含预热）都检查。长连接空闲不消耗次数，后续生成轮次仍需准入。

到点后禁止新请求，已经开始的 HTTP/SSE 或 WebSocket 生成轮次允许正常结束。**排班空档不等于从最后响应结束计算的连续静默时长**：本版没有实现“最后一个请求完成后再休息 N 小时”的状态机，也不会为了下班强行终止用户正在接收的输出。修改班次不追溯历史在途请求。

## 单账号总限速

`request_limits` 每项包含 `account_id` 和 `rpm`，账号不可重复，RPM 为 1–10000 的整数。通过 Redis 原子滑动窗口记录最近 60 秒的发送准入；恰好 60 秒前的记录退出窗口。所有用户、API Key、分组、影子账号及共享同一 Redis 的应用实例使用同一个根账号桶。

失败、重试、HTTP 回退、WebSocket 预热均消耗一次准入，不退款；在领取次数前拒绝的休息或限速请求不消耗次数。领取后恰逢下班或配置失效而被最终复核拒绝时，已领次数保守保留。已经消耗的次数不因改配置或应用重启清零，减少上限可能立即阻止新请求。未配置限速的账号不使用计数桶。

这是总次数上限，**不提供匀速发送或突发平滑**，可以在很短时间内用完额度；并发上限和 token 用量上限也不由 RPM 替代。Redis 记录约 61 秒后过期，不含凭据或正文。Redis 重启、数据丢失或人工清库会重置窗口，部署应使用现有持久化和共享 Redis，不能为不同应用实例配独立 Redis 后期待全局限速。

保护覆盖核心 HTTPUpstream 账号出口（含经此出口的合成探测、附件上传、结果查询和下载）、账号测试、OpenAI OAuth 插件入口和核心 WebSocket 生成发送。一个用户请求可能包含多个上游尝试并消耗多次；未绑定账号凭据的公共资源下载不计。插件协议无法逐次拦截插件内部重试，受保护账号命中插件路由时直接返回 503，不静默放行或改走其他出口。使用这两项保护前须关闭相应插件绑定，采用核心传输；未配置保护的账号插件行为不变。OAuth 刷新、额度查询等独立后台网络请求不属于模型请求计数。

达到上限时允许选择其他合法账号；本地拒绝不记录为上游或代理故障，也不扣账号调度健康度。候选阶段已经没有可用账号时，返回既有无可用账号错误。发送阶段触发保护而换号耗尽时，HTTP 返回 429（`account_rate_limited`）或 503（`account_resting` / `account_protection_unavailable`），并提供 `Retry-After`。休息错误的 Retry-After 是重试建议，不是预计上班时间。已经开始的流式响应通过流错误结束，不能更改已发送的 HTTP 状态。WebSocket 后续轮次拒绝时要求重连，避免重放首轮。

## 两种轮候模式

手动模式按三个时段修改账号优先级，默认 `00:00–08:00`、`08:00–16:00`、`16:00–24:00`，时段内/外优先级默认 1/50。只开启手动模式而不开严格休息时，时段外账号仍可接单。首次接管保存原优先级；停用、移除或切换智能模式时事务内恢复原值。原值由后端维护，不接受客户端提交。

智能模式根据实际首字耗时维护健康状态，不按历史的固定轮换周期或主力数量轮转：

- 正常：保留原优先级。
- 等待：采样窗口内连续慢请求达到阈值后降权等待，仍可作为备用，并非严格休息。
- 观察恢复：冷却结束后间隔放行探测，单账号最多一个在途探测，连续健康后恢复正常。
- 不可用：类型、状态、到期或其他调度限制使账号不可用。

默认首字阈值 20 秒、连续慢/健康各 3 次、采样窗口 10 分钟、冷却 30 分钟、等待优先级 50、观察间隔 60 秒。失败或缺少首字数据不算健康。`periods`、`rotation_minutes`、`quota_reserve_percent` 只兼容历史配置，不参与当前智能调度。严格休息优先于健康探测；休息期间不为探测破例。

## 生效与异常行为

配置保存成功在当前实例立即发布内存快照；其他实例由每 15 秒的 worker 刷新。跨实例没有同步广播事务，保存后的短暂同步期内可能仍按旧配置执行，应查看各实例就绪状态后验收。排班时间边界按发送时当前北京时间判断，不等待优先级 worker 更新。

快照未初始化或超过 45 秒未成功刷新时，OpenAI OAuth 新请求拒绝准入，避免未知配置时绕过保护；此时即使此前未启用保护也需要等待配置服务恢复。非 OAuth 账号不受此休息检查影响。受限账号的 Redis 出错或无法解析账号归属时拒绝发送。配置存储、账号仓储或 Redis 恢复后自动恢复；无需删除计数键。保护启用时 HTTP 出口会核实账号归属，增加一次账号仓储查询。

管理状态每 20 秒刷新，显示已保存配置的状态和最近 60 秒已用次数，不领取请求次数。状态读取失败或版本不同显示不可用，不把未保存配置当作实际运行状态。状态中的「允许新请求」只代表保护检查，不保证额度、分组和其他调度条件都满足。

## 接口与持久化

- `GET /api/v1/admin/intelligent-ops/time-rotation`：读取配置。
- `PUT /api/v1/admin/intelligent-ops/time-rotation`：整体保存，必须携带读取时的 `revision`，冲突返回 409。
- `GET /api/v1/admin/intelligent-ops/time-rotation/status`：快照状态，可选 `group_id`。`accounts` 保留智能健康状态；新增 `protection` 列表包含 `account_id`、`state`、`rpm`、`used`，手动模式也返回。没有限速或 Redis 不可读时 `used` 为 null。

配置字段为 `enabled`、`revision`、`mode`、`slots`、`smart`、`strict_rest`、`request_limits`。`slots` 包含 `start`、`end`、`account_ids`、`active_priority`、`inactive_priority`。配置仍保存于现有 `settings.account_time_rotation` 记录，无数据库迁移。保存时校验所有新增保护引用为独立 OpenAI OAuth 账号。配置行锁、优先级变更及调度 outbox 保持原事务机制。

回滚到不支持保护的版本会失去硬限制，必须先评估容量与访问策略；旧版本不会执行这些新增字段。正式上线仍需同 commit 的 staging 验证与用户明确授权。排班与限速用于容量管理，不保证任何上游账号不会被限制或封控。
