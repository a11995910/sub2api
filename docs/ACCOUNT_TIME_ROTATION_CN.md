# 账号轮候、严格休息、总限速与随机休息

管理入口为「智能运维 → 账号轮候」。仅管理选中的独立 OpenAI OAuth 根账号。严格休息、总限速和随机休息同步约束这些根账号的影子账号；未配置保护的账号保持原调度规则。所有排班固定使用北京时间，顶部「启用轮候」是手动轮候、智能轮候和全部账号保护的总开关。旧配置的 `strict_rest` 默认为 false，`request_limits` 默认为空，`random_rest` 缺省时不启用。

## 配置方法

1. 选择手动或智能轮候，开启顶部总开关。
2. 开启「排班外严格休息」，在三个时段中选中根账号并设置可接请求的时间。每账号只能属于一段，允许跨午夜、重叠班次和空档。未排班的账号不受休息限制。
3. 点击「添加账号限速」，为每个需要限制的根账号设置滚动 60 秒总次数，例如先以 10 次作容量试运行参数，观察排队、拒绝率和业务响应后调整。这不是上游安全阈值。
4. 保存，查看下方「已保存配置的保护状态」。分组、模型、额度和账号状态仍决定账号是否真正可用。

需要全天服务时，应保证每个业务分组在各时段都有可用账号。不能只按全站账号数量平均分班。某分组的全部账号休息或触及上限后，系统可能返回无可用账号；不会放开保护来兜底。RPM 触顶后可在原账号限时等待，现有并发排队仍独立生效。

## 严格休息

`strict_rest=true` 时，`slots` 同时作为硬性准入时间表，手动和智能模式均适用。区间包含开始、不包含结束，结束支持 `24:00`，结束早于开始表示跨午夜。禁止为选中账号配置 `00:00–24:00`；起止相同也不合法。

调度候选、等并发槽复核及发送上游前检查时间。粘性会话、续链、兜底和重试不能绕过发送检查。HTTP 每次发送尝试、WebSocket 每个 `response.create`（含预热）都检查。长连接空闲不消耗次数，后续生成轮次仍需准入。

到点后禁止新请求，已经开始的 HTTP/SSE 或 WebSocket 生成轮次允许正常结束。**排班空档不等于从最后响应结束计算的连续静默时长**：严格排班本身不会从最后一个请求完成时重新计算下次上班时间，也不会为了下班强行终止用户正在接收的输出；需要从在途结束后计时，可另行启用下文的随机休息。修改班次不追溯历史在途请求。

## 单账号总限速

`request_limits` 每项包含 `account_id` 和 `rpm`，账号不可重复，RPM 为 1–10000 的整数。通过 Redis 原子滑动窗口记录最近 60 秒的发送准入；恰好 60 秒前的记录退出窗口。所有用户、API Key、分组、影子账号及共享同一 Redis 的应用实例使用同一个根账号桶。

失败、重试、HTTP 回退、WebSocket 预热均消耗一次准入，不退款；在领取次数前拒绝的休息或限速请求不消耗次数。领取后恰逢下班、随机休息或配置失效而被最终复核拒绝时，已领次数保守保留。已经消耗的次数不因改配置或应用重启清零，减少上限可能立即阻止新请求。未配置限速的账号不使用计数桶。

这是总次数上限，**不提供匀速发送或突发平滑**，可以在很短时间内用完额度；并发上限和 token 用量上限也不由 RPM 替代。Redis 记录约 61 秒后过期，不含凭据或正文。Redis 重启、数据丢失或人工清库会重置窗口，部署应使用现有持久化和共享 Redis，不能为不同应用实例配独立 Redis 后期待全局限速。

保护覆盖核心 HTTPUpstream 账号出口（含经此出口的合成探测、附件上传、结果查询和下载）、账号测试、OpenAI OAuth 插件入口和核心 WebSocket 生成发送。一个用户请求可能包含多个上游尝试并消耗多次；未绑定账号凭据的公共资源下载不计。插件协议无法逐次拦截插件内部重试，受保护账号命中插件路由时直接返回 503，不静默放行或改走其他出口。使用账号保护前须关闭相应插件绑定，采用核心传输；未配置保护的账号插件行为不变。OAuth 刷新、额度查询等独立后台网络请求不属于模型请求计数。

限速采用“已有会话保留原账号等待、新会话提前分流”：

- 调度不会仅因本地 RPM 触顶而清除已有会话绑定；受限账号的粘性优先于加权粘性调度。账号禁用、上游故障、健康降级、分组权限或严格休息等其他条件仍按原规则处理，不保证账号在所有情况下永不切换。
- 新会话在最近 60 秒用量达到 `RPM - max(1, floor(RPM / 5))` 时不再分配到该账号，约留 20% 给已有会话；RPM=1 时不预留。根账号与影子账号共用此判断。没有其他合法候选时返回无可用账号，不借用预留额度。候选检查不预占次数，并发竞态仍由发送层硬上限兜底。
- 实际发送触顶后，HTTP、WebSocket 每轮、重试及预热均在原根账号的 Redis 队列等待，最多 65 秒；客户端更早取消或超时则提前退出。每个根账号在所有应用实例上合计最多 `min(RPM, 32)` 个等待者。排队不计入已用次数、不抬高硬上限；已选账号的并发槽位可能在等待期间保持占用。
- 队列满返回 429 `account_rate_limit_queue_full`，等待超时返回 429 `account_rate_limit_wait_timeout`，并给出 `Retry-After: 1` 的重试建议。两种错误均停止自动换号，保留原粘性绑定。正常队列退出立即清理；实例崩溃或 Redis 故障导致清理失败时，90 秒租约兜底释放。Redis 数据丢失可能清空窗口与队列，仍依赖持久化。
- 等待每秒重新检查配置、休息边界与原子额度。移除限速后恢复发送；进入严格休息或随机排空/休息后立即结束等待、解除原绑定并重新选号，不能借粘性继续发送。配置过期或 Redis 不可用时拒绝发送，不绕过限制。
- WebSocket 等待不会主动关闭连接或更改 `previous_response_id`、当前输入与缓存归属。启用限速时入口使用单一后台读循环，处理 ping、断线，并仅缓冲一个待处理数据帧；超过缓冲上限会关闭连接。等待期间每 15 秒发送一次 ping；断线、入口取消或 `response.cancel` 及时停止等待。取消轮次后当前实现结束连接，客户端需重连；不会继续发送被取消的轮次。网络写超时与首字超时从取得额度后的实际发送开始计算。
- 本地限速等待单独计量，从账号健康评估的首字和总耗时中扣除；用户请求日志仍包含实际总耗时。限速本身不计为上游或代理故障。

已经开始的 HTTP/SSE 回复不因触顶或下班而中途截断。休息时下一条请求不等待原账号恢复，调度或发送前发现休息即解除当前会话和响应 ID 绑定，重新选择符合分组、模型、额度和保护条件的账号；没有可用账号时及时返回错误。空闲绑定在再次访问时检查并失效。WebSocket 后续轮次仅在当前连接保存了完整输入和成功输出、响应 ID 链匹配、工具调用上下文完整时自动迁移当前轮；历史捕获上限为 8 MiB。跨连接历史缺失、终态不完整、超过上限或透传连接使用 session.update 时及时提示重连，客户端须携带完整历史重试当前轮，不能重放首轮。排队超时或配置错误仍可能结束连接。发送阶段休息或配置错误继续返回 503（`account_resting` / `account_protection_unavailable`）；休息的 Retry-After 只是建议，不是预计上班时间。已提交的流式响应只能发送流内错误，无法修改 HTTP 状态。缓存最终是否命中取决于上游及请求内容，本机制只减少本地限速造成的不必要换号与重连。

## 两种轮候模式

手动模式按三个时段修改账号优先级，默认 `00:00–08:00`、`08:00–16:00`、`16:00–24:00`，时段内/外优先级默认 1/50。只开启手动模式而不开严格休息时，时段外账号仍可接单。首次接管保存原优先级；停用、移除或切换智能模式时事务内恢复原值。原值由后端维护，不接受客户端提交。

智能模式根据实际首字耗时维护健康状态，不按历史的固定轮换周期或主力数量轮转：

- 正常：保留原优先级。
- 等待：采样窗口内连续慢请求达到阈值后降权等待，仍可作为备用，并非严格休息。
- 观察恢复：冷却结束后间隔放行探测，单账号最多一个在途探测，连续健康后恢复正常。
- 不可用：类型、状态、到期或其他调度限制使账号不可用。

默认首字阈值 20 秒、连续慢/健康各 3 次、采样窗口 10 分钟、冷却 30 分钟、等待优先级 50、观察间隔 60 秒。失败或缺少首字数据不算健康。`periods`、`rotation_minutes`、`quota_reserve_percent` 只兼容历史配置，不参与当前智能调度。严格休息优先于健康探测；休息期间不为探测破例。

## 生效与异常行为

配置保存成功在当前实例立即发布内存快照；其他实例由每 15 秒的 worker 刷新。跨实例没有同步广播事务，保存后的短暂同步期内可能仍按旧配置执行，应查看各实例就绪状态后验收。排班时间边界按发送时当前北京时间判断，不等待优先级 worker 更新。

快照未初始化或超过 45 秒未成功刷新时，OpenAI OAuth 新请求拒绝准入，避免未知配置时绕过保护；此时即使此前未启用保护也需要等待配置服务恢复。非 OAuth 账号不受此休息检查影响。受限账号的 Redis 出错或无法解析账号归属时拒绝发送。配置存储、账号仓储或 Redis 恢复后自动恢复；无需删除计数键。保护启用时 HTTP 出口会核实账号归属，增加一次账号仓储查询。

管理状态每 20 秒刷新，显示已保存配置的状态和最近 60 秒已用次数，不领取请求次数。状态读取失败或版本不同显示不可用，不把未保存配置当作实际运行状态。状态中的「允许新请求」只代表保护检查，不保证额度、分组和其他调度条件都满足。

## 接口与持久化

- `GET /api/v1/admin/intelligent-ops/time-rotation`：读取配置。
- `PUT /api/v1/admin/intelligent-ops/time-rotation`：整体保存，必须携带读取时的 `revision`，冲突返回 409。
- `GET /api/v1/admin/intelligent-ops/time-rotation/status`：快照状态，可选 `group_id`。`accounts` 保留智能健康状态；新增 `protection` 列表包含 `account_id`、`state`、`rpm`、`used`，手动模式也返回。没有限速或 Redis 不可读时 `used` 为 null。

配置字段为 `enabled`、`revision`、`mode`、`slots`、`smart`、`strict_rest`、`request_limits`、`random_rest`。`slots` 包含 `start`、`end`、`account_ids`、`active_priority`、`inactive_priority`。配置仍保存于现有 `settings.account_time_rotation` 记录，无数据库迁移。保存时校验所有新增保护引用为独立 OpenAI OAuth 账号。配置行锁、优先级变更及调度 outbox 保持原事务机制。

回滚到不支持保护的版本会失去硬限制，必须先评估容量与访问策略；旧版本不会执行这些新增字段。正式上线仍需同 commit 的 staging 验证与用户明确授权。排班与限速用于容量管理，不保证任何上游账号不会被限制或封控。

## 随机休息（默认关闭）

管理页「启用随机休息」独立控制此功能，并受顶部轮候总开关约束。手动和智能模式都可使用；只作用于选择的 OpenAI OAuth 根账号及其影子账号。关闭时不拦截请求。启用后可配置：

| 字段 | 含义 | 范围 | 表单初值 |
|---|---|---|---|
| `random_rest.enabled` | 随机休息开关 | 布尔 | false |
| `random_rest.account_ids` | 参与的根账号 | 正整数，不重复；启用时非空 | 空 |
| `check_interval_minutes` | 每隔多少分钟抽签一次 | 1–1440 整数 | 5 |
| `probability_percent` | 每次抽签触发概率 | 0–100 整数 | 20 |
| `min_rest_minutes` | 最短休息 | 1–1440 整数 | 3 |
| `max_rest_minutes` | 最长休息，不小于最短值 | 1–1440 整数 | 8 |
| `max_work_minutes` | 从本轮首个准入开始，最多工作多久即停止接单；0 关闭兜底 | 0–1440 整数 | 90 |

这些初值仅为配置示例，不是使用记录推导的安全阈值。保存未启用的配置不会自动启动随机休息。若概率与最长工作同时为 0，则不会主动休息。

状态流转为「工作 → 排空 → 休息 → 等待下一次工作」：

- 首个实际准入启动工作时钟。抽签按时间间隔进行，不按每个请求抽签；多实例共用 Redis 原子状态，一个到期检查只抽一次。服务 worker 每约 15 秒推进一次，发送前和状态查询也会检查；无请求时不补抽历史遗漏次数。工作时钟包含轮次之间的自然空档，并非 CPU 忙碌时长。达到最长工作时间即停止接单，但不强行截断现有请求。
- 触发时从最短至最长休息之间，按整数分钟均匀抽取时长。立即拒绝新的发送，等待已登记的在途请求结束，最后一个结束后才开始计算休息截止时间。HTTP 以响应体读完、读取出错或关闭作为本地结束；WebSocket 以每轮终态或转发退出作为本地结束；限速等待与空闲 WS 连接不算在途。
- 随机排空或休息中的账号不接新老会话请求。下一条请求发现休息后解除原粘性绑定并重新选号，不等待休息结束；在途回复正常结束。发送前竞态发现休息时，`account_random_draining` / `account_random_resting` 允许按现有换号预算选择其他可用账号。无可用账号或无法安全重建 WS 当前轮时及时报错，不无限等待。随机休息不进入 65 秒 RPM 队列；已经排队的请求在下一次检查时退出并重新选号。换号可能重新建立上游缓存。
- 严格排班仍优先检查，不能借随机休息结束延长工作时段。修改概率、时长等参数不会清空现有在途、已开始的排空或休息；新时长用于下次触发。修改抽签间隔从下次安排检查起采用新间隔，当前已安排的检查时间保留。停用或移除账号会取消该账号随机准入限制，重新启用会续用保留的状态；修改其他设置或应用重启不重置休息。

### 观测范围与异常恢复

首次启用或新增账号应选择账号无在途请求时操作：本功能只能登记启用后经过本实例保护出口的请求，无法追溯启用前、旧版本实例或其他客户端直接发出的调用。所有接流实例应更新到同一版本并共享持久化 Redis。这里的零在途是本网关能观测的请求结束；网络断开不等于能够证明上游远端计算立刻停止。

状态列表增加 `random_state`（working/draining/resting）、`in_flight` 和 `random_rest_until`。已有 `state` 增加 `account_random_draining`、`account_random_resting`。状态读取不领取额度，但可能推进已到期的抽签和休息状态。

Redis 键为 `account_random_rest:{根账号ID}` 和 `account_random_rest:{根账号ID}:active`，只保存状态、时间与随机请求令牌，不含正文或凭据。在途集合**没有自动过期**：不能根据租约失效推断上游请求已结束。进程崩溃、强杀或结束时 Redis 长时间不可用可能留下记录；清理会最多重试三次，失败记录账号 ID，随后可能一直停留在排空中。正常结束使用独立于客户端取消的清理上下文，同一结束回调可重复调用但仅清理一次。

若排空长期不结束，先核查所有实例、旧进程、连接与上游在途请求，停止该账号新增调用并确认残留请求已经结束。随后由运维仅清除该根账号 `:active` 集合中的已核实残留令牌；无法逐个核实时不要删除整个集合。保留状态键，下一次 worker 检查确认集合为空后会开始完整休息时长。不得把清空 Redis 或关闭再开启当作常规恢复手段。Redis 数据丢失会丢失在途与休息状态，恢复后须先核实流量再启用此功能。
