## 目标

为使用正价 Pro 等公开分组的用户提供可核对的 OAuth 号池状态，同时让用户在自己的使用记录中看到每次请求实际命中的 OAuth 账号名称。

功能必须满足以下约束：

1. 是否公开号池由分组级开关控制，默认关闭。
2. 号池页面只显示 OAuth 账号，不显示 API Key、Setup Token、Service Account 或其他认证类型账号。
3. 号池页面只读，不提供导出、刷新、测试、额度重置、启停或其他账号操作。
4. 号池卡片只展示账号名称、额度和重置时间。
5. 额度展示与管理端账号页共用同一套展示组件和后端额度归一化逻辑，不能维护两套实现。
6. 使用记录仅在记录属于当前用户、实际分组已公开号池且实际命中 OAuth 账号时展示账号名称。
7. 普通用户接口不得暴露账号凭证、内部备注、代理、错误详情或完整账号对象。

## 已核实的当前实现

### 数据与调度

- `usage_logs.account_id` 已记录请求实际命中的账号，无需修改调度器或用量写入流程。
- `usage_logs.group_id` 记录请求最终使用的有效分组。请求发生自动分组承接时，应按该实际分组判断号池是否公开，而不是按 API Key 原始绑定分组判断。
- `accounts` 与 `groups` 通过 `account_groups` 关联。
- 当前 `groups` 尚无号池公开字段。
- 普通用户 Usage DTO 当前返回 `account_id`，但刻意不返回账号摘要；管理员 Usage DTO 会返回仅含 ID、名称的账号摘要。
- 使用记录列表查询完成后会批量加载 User、APIKey、Account、Group 和 Subscription，已经避免列表逐行查询。
- `GET /api/v1/usage/:id` 当前只读取 `usage_logs` 主表，没有加载 Account 和 Group；实现详情展示时需要补充单条关联加载。

### 额度逻辑

- 管理端账号页通过 `AccountUsageCell.vue` 展示账号额度。
- 5 小时、7 天额度条和重置倒计时由 `UsageProgressBar.vue` 实现。
- `AccountUsageCell.vue` 同时包含主动额度查询和 OpenAI 额度重置操作，不能整体复用到普通用户页面。
- `AccountUsageService.GetUsage` 对 OpenAI OAuth 可能发起主动上游探测，普通用户打开号池页面时不得直接调用该行为。
- 现有 `GetPassiveUsage` 只支持 Anthropic OAuth / Setup Token，不能直接用于 OpenAI OAuth。
- OpenAI OAuth 的 5 小时、7 天额度快照已经保存在账号 `extra` 的 `codex_*` 字段中，并由 `applyExtraToUsage`、`buildCodexUsageProgressFromExtra` 归一化为 `UsageInfo`。

### 线上核实快照

2026-07-27 对正式环境进行了只读核实，目标分组为 `pro正价分组`，分组 ID 为 `74`，平台为 `openai`，状态为启用。分组当时绑定：

- `CPA pro`：`apikey`，不得展示。
- `Pro正价`：`oauth`，应展示。

`Pro正价` 当时已有 5 小时和 7 天额度及重置时间快照。该快照仅用于确认现有数据链路可用，开发和测试不能依赖固定额度数值。

## 最终产品规则

### 管理端分组开关

在分组创建和编辑表单增加“号池对用户可见”开关：

- 字段名：`oauth_pool_visible`
- 默认值：`false`
- 开启：符合访问权限的用户可以在号池页面查看该分组的 OAuth 账号；对应使用记录可以展示实际命中的 OAuth 账号名称。
- 关闭：号池页面不返回该分组；对应使用记录不展示账号名称。
- 分组复制：沿用源分组值，但复制出的分组继续遵循现有默认停用规则。
- 分组删除：不需要额外清理账号或用量历史。

### 用户号池页面

- 页面名称：`号池状态`
- 建议路由：`/account-pool`
- 入口：普通用户侧导航和管理员“我的账户”导航共同使用现有个人导航声明。
- 页面布局：按可见分组分区，每个 OAuth 账号使用独立卡片；不使用表格。
- 卡片内容：账号名称、5 小时额度、5 小时重置时间、7 天额度、7 天重置时间。
- 页面不显示分组或账号的内部 ID。
- 页面不提供导出按钮，也不复用使用记录页现有 CSV 导出逻辑。
- 页面不提供任何账号操作按钮。
- 页面可以静默重新读取服务端快照，但不得由普通用户请求触发 OAuth 上游额度探测。
- 重置时间倒计时复用现有前端分钟级更新逻辑。

账号进入号池返回结果必须同时满足：

1. 用户按现有分组访问规则有权使用该分组。
2. 分组未删除、状态启用且 `oauth_pool_visible = true`。
3. 账号仍与该分组关联、未删除、状态启用且 `type = "oauth"`。

临时不可调度、限流或额度耗尽的 OAuth 账号仍属于号池，应继续展示其额度和重置时间；永久停用或软删除账号不展示。API Key 账号即使处于同一公开分组也必须在查询层过滤，不能只依赖前端隐藏。

页面状态：

- 加载中：展示尺寸稳定的卡片骨架，避免布局跳动。
- 无可见分组或无 OAuth 账号：展示统一空状态，不暴露分组是否存在 API Key 账号。
- 账号暂无额度快照：仍展示账号名称，额度区域显示暂无数据，不发起主动探测。
- 接口失败：展示统一错误状态，不输出上游或账号内部错误详情。

### 用户使用记录

用户使用记录列表和详情增加可选的 OAuth 账号名称展示。展示条件必须全部满足：

1. 记录所有者是当前登录用户。
2. 记录的实际 `group_id` 对应分组开启 `oauth_pool_visible`。
3. 记录的实际 `account_id` 对应账号存在且 `type = "oauth"`。

不满足条件时不返回账号摘要，前端显示为空。具体规则：

- 公开分组命中 OAuth：展示账号名称。
- 公开分组命中 API Key：不展示账号 ID或名称。
- 未公开分组命中 OAuth：不展示账号 ID或名称。
- 自动承接后命中公开分组 OAuth：按 `usage_logs.group_id` 的实际承接分组展示。
- 其他用户请求同一记录详情：继续返回无权限。
- 账号改名后历史记录展示当前账号名称；本功能不增加账号名称历史快照字段。
- 账号已删除或关联数据缺失：不展示账号名称，使用记录主体仍正常返回。
- 使用记录页面现有 CSV 导出不增加 OAuth 账号字段，账号对应关系只在用户自己的页面中查看。

## 后端实施方案

### 数据库与 Ent

新增迁移：`backend/migrations/192_group_oauth_pool_visible.sql`。

```sql
ALTER TABLE groups
    ADD COLUMN IF NOT EXISTS oauth_pool_visible BOOLEAN NOT NULL DEFAULT FALSE;
```

同步修改：

- `backend/ent/schema/group.go`
- Ent 生成文件
- Group service model、Repository、管理员创建/更新参数和 DTO mapper
- 分组复制字段映射
- 迁移回归测试

该字段默认关闭，旧数据和旧调用方不传值时保持现有行为。不需要回填，不需要索引；查询号池时仍应以用户可访问分组集合为入口，避免对单个布尔字段做无边界扫描。

### 用户号池接口

建议新增认证只读接口：

```text
GET /api/v1/oauth-account-pool
```

接口使用现有 JWT 认证和用户模式守卫。服务层必须复用现有“用户可访问分组”判断，不另写一套公开分组、专属分组和订阅分组权限规则。

建议公开响应结构：

```json
{
  "groups": [
    {
      "name": "pro正价分组",
      "accounts": [
        {
          "name": "Pro正价",
          "usage": {
            "five_hour": {
              "utilization": 0,
              "resets_at": "2026-07-27T16:25:15+08:00"
            },
            "seven_day": {
              "utilization": 29,
              "resets_at": "2026-08-02T03:18:42+08:00"
            }
          }
        }
      ]
    }
  ]
}
```

响应只允许包含页面所需字段。禁止返回：

- Account ID、Group ID
- Credentials、Extra 原始内容
- Notes、Proxy、ErrorMessage
- 调度优先级、并发、倍率、上游账号标识
- 主动查询或额度重置能力标识

### 额度服务复用

在 `AccountUsageService` 内抽取“从已加载账号构建缓存额度”的纯方法：

- OpenAI OAuth 复用 `applyExtraToUsage` 和 `buildCodexUsageProgressFromExtra`。
- Anthropic OAuth 复用现有被动额度构建逻辑，但公开页不接纳 Setup Token。
- 纯构建方法不得访问上游，不得更新账号，不得触发额度重置。
- 管理端 `GetUsage` 和用户号池服务共同调用归一化方法，保证字段口径一致。
- 号池列表应批量加载账号，避免对每张卡片重复查询 Account。
- 用户接口不需要账号窗口费用统计，避免为每个账号额外聚合 `usage_logs`。

当前验收目标是 OpenAI 正价 Pro 分组。其他平台的 OAuth 账号只有在现有缓存快照能够映射为公开额度窗口时才展示额度；无可映射快照时按“暂无额度数据”处理，不能为补数据而从用户接口调用第三方。

### 使用记录 DTO 与关联加载

普通用户 DTO 增加只含名称的可选公开账号摘要，例如：

```json
{
  "oauth_account": {
    "name": "Pro正价"
  }
}
```

实施要求：

- 普通用户 mapper 和管理员 mapper 分开处理可见性，管理员现有账号摘要行为保持不变。
- 普通用户的 `account_id` 改为可省略字段；不满足公开条件时不得继续泄露 API Key 或未公开 OAuth 的内部账号 ID。
- 列表直接利用现有批量关联加载结果判断 Account 和 Group，不新增 N+1 查询。
- 详情查询补充 Account 和 Group 关联加载后再执行相同可见性判断。
- 可见性判断提取为后端公共方法，列表和详情不能各自维护一套条件。
- 用户所有权检查必须在返回 DTO 前完成。

`account_id` 从普通用户响应中收紧为条件字段可能影响依赖该未公开内部字段的旧客户端。实施前应搜索仓库内所有消费方，并在 API 合约测试中固定新的脱敏规则；管理员接口不受此调整影响。

## 前端实施方案

### 共享额度组件

从 `AccountUsageCell.vue` 抽取纯展示组件，建议命名：

```text
frontend/src/components/account/OAuthUsageWindows.vue
```

组件职责：

- 接收归一化后的 `AccountUsageInfo` 或等价公开窗口类型。

管理端 `AccountUsageCell.vue` 继续负责主动查询和额度重置操作，并在纯展示区域使用新组件。用户号池卡片只使用纯展示组件，不渲染 `OpenAIQuotaResetCell`。

### 使用记录页面

- 在用户使用记录列表增加“OAuth账号”显示列，字段为空时显示 `-`。

- 不在筛选项中增加账号筛选，避免把内部账号维度扩展成用户可枚举接口。
- 管理端使用记录页面维持现有账号展示和筛选能力。

## staging 验收清单

使用与正式环境隔离的 staging 数据准备一个同时绑定 OAuth 和 API Key 的 OpenAI 标准分组：

1. 公开开关关闭时，号池页面不出现该分组，使用记录不显示账号。
2. 开启开关后，号池页面只出现 OAuth 卡片，不出现 API Key。
3. OAuth 卡片额度、颜色、百分比和重置时间与管理端账号页一致。
4. 普通用户停留在页面不会触发 OAuth 上游探测或额度重置。
5. 请求命中 OAuth 后，当前用户使用记录列表和详情显示账号名称。
6. 请求命中 API Key 后，使用记录不显示账号。
7. 使用记录导出文件不包含账号名称。
8. 另一用户不能读取该用户的使用记录详情。
9. 自动承接到公开正价分组并命中 OAuth 时，按实际分组展示账号。
10. 移动端和桌面端卡片无文字溢出、重叠或布局跳动。
11. 管理端账号页主动查询、额度重置及额度展示不受影响。

## 风险与回滚

- 上游探测风险：用户接口若误用 `GetUsage`，可能被大量页面访问放大为 OAuth 上游请求。必须以“不发网络请求”的测试替身固定该边界。
- 数据泄露风险：不能把完整 Account DTO 或 `extra` 直接返回用户。必须定义专用公开 DTO，并在 API 合约测试中校验禁止字段。
- 历史记录风险：历史记录只保存 `account_id`，账号改名后显示当前名称；账号删除后无法继续展示名称。这是当前计划的明确口径，不增加历史快照迁移。
- 性能风险：号池和使用记录必须批量加载关联，不能按卡片或日志逐条查询。
- 兼容风险：普通用户 `account_id` 脱敏可能影响非官方客户端，实施前需完成仓库内消费方检查和接口合约回归。
- UI 复用风险：共享组件只抽取纯额度展示，管理端按钮和管理员 API 继续留在 `AccountUsageCell.vue`，避免普通用户页面获得操作能力。

紧急关闭优先将相关分组的 `oauth_pool_visible` 设置为 `false`，无需删除账号或历史用量。数据库字段采用向前兼容的默认值，回滚应用镜像时旧版本会忽略该字段；如需删除字段，必须另建经过 staging 验证的反向迁移，不能直接在线手工删除。
