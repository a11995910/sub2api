# 备份机核心功能发布验收设计

## 结论

在备份机 `192.220.36.75` 的现有 Sub2API 测试实例上原地完成核心功能回归。测试实例使用独立 PostgreSQL、Redis 和数据目录，允许修改测试数据；生产服务器与三份备份归档始终只读。支付、邮件、OAuth、Webhook 和飞书等外部集成不纳入本轮验收，也不得为了显示菜单而配置生产密钥。

备份机验收是发布前的完整核心回归，但不能替代正式 VPS 上同一 `main` commit 的隔离 staging 门禁。

## 环境边界

- 测试应用、PostgreSQL、Redis 和应用数据全部位于备份机的独立运行目录。
- 归档目录不挂载进测试容器；测试前后核对三份归档数量与 SHA-256。
- 不连接生产数据库，不启用恢复得到的生产用户、API Key、支付通道或外部通知凭据。
- 测试管理员是唯一长期启用的管理员，并使用测试环境独立密码。
- 创建 2 至 3 个带测试标识的临时普通用户和测试 API Key，供权限与计费验证。
- 仅允许当前确认的三个测试专用上游账号参与真实模型调用。
- 测试数据不要求回滚；验收产生的数据必须可通过测试标识识别。

## 功能范围

### 纳入验收

- 管理员认证、权限与全部非支付菜单。
- 用户、API Key、分组、渠道、上游账号、代理和订阅管理。
- 普通文本请求、真实上游调用、余额扣减与用量记录。
- 图片、批量图片和视频任务的核心状态与计费流程。
- 签到、分销、风控、运维监控、审计日志和异常处理。
- 服务健康、数据库连接、Redis、日志和重启后的配置持久性。

### 明确排除

- 真实充值、支付创建、支付回调、退款和支付到账。
- 真实邮件、短信、OAuth 应用、Webhook 和飞书通知。
- 恢复生产配置、启用生产普通用户或复用生产 API Key。

## 视频冻结余额门禁

异步视频必须使用普通余额计费的临时测试用户和测试 API Key 调用 `/v1/videos`。模型测试台、订阅计费和同步视频不能替代该门禁。

验收至少证明：

1. 创建前按预计费用减少可用余额并增加冻结余额。
2. 明确成功时只结算一次冻结金额并只写入一次用量。
3. 明确 `failed`、`cancelled`、`expired` 或 `error` 且无视频产物时，释放冻结金额且不写消费扣款。
4. 重复轮询、重复失败结果和重复对账不能重复释放。
5. 超时、429、5xx、解析失败或完成但无产物时保持冻结并进入待确认状态。
6. 管理员人工确认失败后只释放一次，余额缓存与数据库结果一致。
7. 测试前后满足可用余额、冻结余额、用量记录和视频账单状态的守恒关系。

确定性失败路径使用备份机本地的受控上游模拟；真实成功路径使用测试专用上游账号做冒烟验证。模拟服务不得出现在生产 compose 或生产运行配置中。

## 执行与失败处理

执行顺序固定为：隔离基线 -> 配置补齐 -> 自动化测试 -> API 回归 -> 视频计费门禁 -> 数据一致性 -> 重启持久性 -> 归档复核。

任一环节发现测试实例引用生产地址、生产密钥、归档目录可写、非测试上游账号启用或账务不守恒，立即停止后续测试。失败只修改测试实例或代码候选，不对生产环境做补偿操作。

## 通过标准

- 所有纳入范围的自动化测试和现场验收通过，无未解释的 5xx、权限绕过或账务差异。
- 视频成功、明确失败、未知状态与人工确认四类账务路径都有可追溯证据。
- 测试前后生产健康只做只读确认，生产数据未写入。
- 三份备份归档的文件数量、大小和 SHA-256 不变。
- 测试实例健康，容器重启后配置仍生效。
- 报告明确列出排除的支付和外部集成，不将其标记为已验证。
