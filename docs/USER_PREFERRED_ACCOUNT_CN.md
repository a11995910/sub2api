# 用户优先调用账号

管理员可在「用户管理 → 编辑用户 → 优先调用账号」中搜索并选择一个上游账号。选择「不指定，使用默认调度」可清除偏好。界面沿用用户编辑的保存按钮，取消编辑不会保存变更。

## 生效规则

- 配置作用于该用户的 API Key 请求，其他用户不受影响；不会修改上游账号自身的全局优先级。
- 仅在本次实际调度的分组包含该账号时优先调用。切换分组、平台不匹配、账号被移出分组或账号已删除时，使用原有组内调度。无分组的请求不应用此偏好，简易模式也不能借此跨组调用。
- 优先账号仍须满足对应入口现有的模型、能力、平台、隐私、额度、限流、利润及调度资格检查。它不获得额外权限、额度或并发。
- 支持并发槽位的生成调度先尝试获取优先账号槽位；槽位已满、会话容量不足或抢槽后账号失效时，继续选择其他合格账号。当前重试已排除的账号不会因用户偏好重新入选；没有合格候选时返回现有的无可用账号错误。
- 普通会话粘性和普通排序之前应用用户偏好。需要原账号的 `previous_response_id` 续聊、守护母账号绑定、受保护会话、已有任务查询等仍保留原绑定，不强行换号。
- OpenAI 兼容平台的新旧调度器、Claude/Gemini 网关、Gemini Messages 兼容入口均应用偏好。批量图片仅在创建任务选择账号时应用，已创建任务继续使用已记录的账号；显式指定的图片提供方不变。
- token count 等原本不占生成槽位的请求继续使用原有并发语义。

## 管理接口与存储

`PUT /api/v1/admin/users/:id` 接受 `preferred_account_id`：

| 值 | 行为 |
| --- | --- |
| 省略或 `null` | 保留原配置 |
| `0` | 清除优先账号 |
| 正整数 | 设置存在且未删除的上游账号 |
| 负数或不存在的账号 | 返回参数错误，不保存 |

暂时停用或限流的账号仍可配置，运行时会自动回退。账号列表加载失败或已选账号被删除时，界面保留原 ID；仅修改其他用户资料不会意外清除或重新校验这项未修改的设置。

完整管理端用户列表、详情和更新响应返回该字段；普通用户资料接口不暴露上游账号 ID，也不允许用户自行修改。受限管理密钥继续遵守原有字段白名单。

迁移 `252_user_preferred_account.sql` 为 `users` 增加非负 `BIGINT` 字段，默认 `0`，现有用户保持原调度。账号软删除后保留配置 ID，调度时检查实际可用性并回退。

用户更新仅写入明确提供的字段，避免旧资料快照覆盖其他并发更新。配置纳入 API Key 认证快照，保存变更后失效该用户的认证缓存；数据库 outbox 为缓存失效提供异步补偿。已开始的请求继续使用请求开始时的配置，新请求在缓存失效后读取更新配置。

## 验证与回滚

测试覆盖优先命中、普通用户不受影响、跨组忽略、模型不支持、停用、限流、并发占满、重试排除、必须保留的绑定、设置及清除、认证快照、管理端字段可见性、搜索加载失败和过期搜索结果。

数据库测试使用独立临时 PostgreSQL，验证完整迁移、读写、认证加载、管理端列表、部分字段更新和 outbox。上线仍需按仓库 staging/prod 门禁执行；本功能开发不代表已部署。

功能回退可先将用户配置清零。旧镜像可忽略新增列；若需要回滚数据库结构，必须先恢复不引用该字段的 `enqueue_user_auth_cache_invalidation()` 函数，再删除新增列。不能在仍运行新代码时删除该列。
